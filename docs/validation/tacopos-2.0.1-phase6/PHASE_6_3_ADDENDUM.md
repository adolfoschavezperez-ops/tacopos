- Para las mismas 30 actualizaciones sintéticas, el código candidato del acumulador convierte sólo cada documento modificado (`docChanges`): 30 conversiones por esos eventos, frente a 60,030 en baseline (reducción calculada de 99.95% del parseo de los 30 callbacks). El archivo candidato no incluye `convertedDocuments`, y el intento de extraerlo después no produjo nuevos eventos; por eso no se declara esa reducción como medición runtime directa. No se activó `operationalActive`, backfill ni filtro histórico.
